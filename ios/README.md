# ScholarMark for iOS (companion MVP)

A native SwiftUI app for students to capture sources, keep notes and quotes, draft citations,
fix missing citation fields, and export. **Local-only:** everything is stored on the device and
nothing syncs with a ScholarMark web account in this version (see [Integration gap](#integration-gap)).

## What a student can do

1. **Capture**: paste a URL, a DOI (`10.1038/…`, `doi:…`, doi.org or publisher links), or a title.
   *Look up details* reads DOI metadata from doi.org (CSL-JSON content negotiation) or the page's
   `citation_*` / Dublin Core / Open Graph meta tags. *Enter details manually* skips the network.
2. **Organize**: projects (one per paper or class) with their own citation style, plus an Inbox.
   Notes per source, and quotes with page, category (same categories as web annotations), and a note.
3. **Draft citations**: Chicago (bibliography, footnote, short note), MLA, APA, with copy and share.
   Quotes copy as a Chicago footnote with the quote embedded, or `"quote" (Author 42)` for MLA/APA.
4. **Review**: the Review tab lists every source missing a field its style needs (required vs.
   suggested), and the editor shows the same hints inline.
5. **Export/share**: bibliography text, Markdown notes and quotes, BibTeX, RIS (Zotero, EndNote,
   Mendeley), and a JSON backup. Exports go through the share sheet (Files, Mail, AirDrop…).

Citation text is a line-by-line port of `server/citationGenerator.ts`, so it matches the web app,
including its current quirks (for example `King, Martin Luther Jr..`, and `by the victors.."` when
a quoted passage ends with a period). Fix those in the TypeScript first, then regenerate the fixtures (below).

## Build and run (Xcode 26+, iOS 26 SDK)

1. On a Mac with **Xcode 26 or later**, open `ios/ScholarMark.xcodeproj`.
2. Select the project → target **ScholarMark** → **Signing & Capabilities**. Pick your **Team** and
   change **Bundle Identifier** from `ai.scholarmark.ios` to one you own.
3. Choose the **ScholarMark** scheme and an iPhone simulator (or a device). Press **⌘R** to run.
4. Press **⌘U** to run the unit tests (the scheme runs the `ScholarMarkCoreTests` package tests).

Without a simulator: `cd ios/ScholarMarkCore && swift test` runs the same tests on macOS.

Deployment target is iOS 18.0; building with Xcode 26 uses the iOS 26 SDK that App Store
submissions require.

**If the project does not open or build**: `ScholarMark.xcodeproj` was written by hand (Xcode 16+
synchronized-folder format) and has not been opened in Xcode yet. Regenerate it from the spec:
`brew install xcodegen && cd ios && xcodegen generate`.

## Layout

```
ios/
  ScholarMark.xcodeproj    app project (synchronized folder: ScholarMark/)
  project.yml              XcodeGen spec that produces the same project
  Config/                  Info.plist additions (export-compliance key)
  ScholarMark/             SwiftUI app: views, LibraryStore, assets, PrivacyInfo.xcprivacy
  ScholarMarkCore/         Swift package (Foundation only): models, citation generator,
                           DOI/URL parsing, metadata lookup, missing-field review, exporters,
                           JSON persistence, and XCTest unit tests
  Tools/generate-citation-fixtures.mjs   builds parity fixtures from the TypeScript generator
  Tools/render-app-icon.mjs              renders the 1024×1024 app icon from the brand mark
```

Regenerate parity fixtures after changing `server/citationGenerator.ts` (Node 22.18+, no install):
`node ios/Tools/generate-citation-fixtures.mjs`.

## Integration gap

The app does not sign in or sync. From the current backend:

- Web sessions use Clerk (`server/auth.ts`); there is no native sign-in flow.
- The OAuth server (`server/oauthRoutes.ts`) issues `mcp_sm_` tokens for MCP clients, but it only
  accepts `https:` or `http://localhost` redirect URIs (`isValidUrl`), and nothing for a native
  app is registered. `requireAuth` does accept these tokens on REST routes, but they are issued
  for the MCP resource, so relying on them from an app would not be a documented contract.
- `sk_sm_` API keys are long-lived secrets pasted into the Chrome extension. Asking students to
  paste one into the app would amount to an app password, so the app does not do it.
- `POST /api/web-clips` needs highlighted text and rebuilds citation data on the server from page
  metadata, so citations edited in the app could not be sent through it unchanged.

What working sync would need (backend and web changes, outside `ios/`):

1. A first-party native OAuth client (PKCE) with a claimed HTTPS redirect (Associated Domains
   plus an `apple-app-site-association` file on the web domain), or an allowed private-use scheme
   for that one client.
2. Tokens whose scope and audience cover the REST endpoints, stored in the iOS Keychain, with
   refresh and revocation.
3. An endpoint that accepts client-supplied `CitationData`, notes, and quotes. The app's JSON
   export already uses the web schema's `CitationData` keys and annotation category names.

## App Store submission gaps

- **App icon**: `AppIcon-1024.png` is generated from the brand mark in `client/public/favicon.svg`
  (full-bleed, opaque RGB, about 20% padding; iOS applies the corner mask). Regenerate it with
  `node ios/Tools/render-app-icon.mjs` (uses the repo's installed `sharp`). Only the universal
  light icon is set; dark and tinted variants are optional and fall back to it. Check it on a
  Home Screen before submitting.
- **Signing**: Team, bundle ID, and an App Store Connect record.
- **Privacy**: the manifest declares no tracking, no collected data, and no required-reason APIs.
  The nutrition label should say "Data Not Collected". A privacy policy URL is still required.
  Lookups contact doi.org or the pasted site only when the user taps *Look up*.
- **Listing**: screenshots (iPhone and iPad), description, support URL, age rating, and review
  notes saying the app works offline without an account.
- **Encryption**: `ITSAppUsesNonExemptEncryption = NO` is set (standard HTTPS only).
- **Not built yet**: a Share/Safari extension (needs an App Group), an iPad split-view layout,
  iCloud sync, PDF capture, and an accessibility and Dynamic Type audit on a device.
- **Purchases**: none, and no web checkout links. Adding paid ScholarMark features later would
  need StoreKit or an approved external-purchase entitlement.
